AWSセキュリティサービスを役割で整理

公開日：2026-08-31 ｜ 更新日：2026-09-03

「どれか1つを選ぶ」のではなく、守る場所が違うサービスを組み合わせて多層防御するのが基本。まずは、何を見て・何を守るのかで整理します。

この記事の要点
11サービスの役割比較どう組み合わせる？GuardDuty・Inspector・MacieCloudTrail・Config・Security Hub全部採用すれば最強？

まずは役割を具体的に比較

サービス名ではなく「何を見るサービスか」を起点にすると、実務でもCLF-C02でも迷いにくくなります。

サービス具体的な役割何を見る？こういう時に使う
IAMユーザー・ロール・権限を管理誰が何をしてよいかS3は閲覧だけ、EC2停止は管理者だけ、のように権限を絞る
KMS暗号化に使う鍵を作成・管理暗号鍵S3・EBS・RDSなどの保存データを暗号化したい
Secrets ManagerパスワードやAPIキーなどの秘密情報を安全に保管・ローテーションDBパスワード、APIキー等認証情報をソースコードや設定ファイルへ直接書きたくない
AWS WAFWebリクエストをルールで許可・ブロックHTTP/HTTPSリクエストSQLインジェクション、XSS、特定IPなどWeb層の攻撃を防ぎたい
AWS ShieldDDoS攻撃からAWS上のサービスを保護大量・異常なネットワークトラフィック大量アクセスでサービス停止を狙う攻撃へ備えたい
GuardDutyAWS環境の不審な挙動や脅威を検出CloudTrail管理イベント、VPC Flow Logs、DNSログ等の信号認証情報の悪用や悪性IPとの通信など「怪しい動き」を見つけたい
Inspectorワークロードのソフトウェア脆弱性などを継続評価EC2、ECRコンテナイメージ、Lambda等古いパッケージや既知の脆弱性を見つけたい
MacieS3内の機密データを発見・分類S3オブジェクト内のデータ個人情報や認証情報など、S3に機密データが含まれていないか確認したい
Security Hubセキュリティ検出結果とセキュリティ態勢を集約GuardDuty・Inspector・Macie等のFindingsや標準チェック複数サービスの結果を一か所で確認・優先順位付けしたい
CloudTrailAWS API操作を記録誰が・いつ・どのAPIを実行したか「誰がEC2を削除した？」「IAM設定を変えた？」を追跡したい
AWS Configリソース設定の履歴を記録し、ルールへの準拠を評価リソースの設定状態と変更S3が公開設定になっていないか等を継続的に確認したい

「どれかを選ぶ」より、役割を重ねる

例えばインターネット公開のWebサービスなら、入口でShieldとWAF、サーバー側でInspector、環境全体でGuardDuty、操作履歴はCloudTrailというように守る場所が違います。

ShieldDDoS対策
WAFWeb攻撃をフィルタ
ALB通信を振り分け
EC2アプリを実行

裏側では： IAMで権限、KMSで暗号化、Secrets Managerで秘密情報、Inspectorで脆弱性、GuardDutyで不審挙動、CloudTrailで操作履歴、Configで設定状態を確認し、Security Hubに結果を集約するイメージです。

最重要：GuardDuty・Inspector・Macieの違い

問題文のキーワード選ぶサービス考え方
不審な挙動・脅威・悪性IPGuardDuty動きを見て「怪しくないか」を検出
脆弱性・CVE・古いソフトウェアInspector攻撃される前の「弱点」を探す
S3・個人情報・機密データMacieS3の中に「守るべきデータ」がないか探す

一言暗記： GuardDuty = 怪しい動き / Inspector = 脆弱性 / Macie = S3の機密情報。

CloudTrail・Config・Security Hubも混同しやすい

知りたいことサービス例
誰が何を操作した？CloudTrail誰がIAMポリシーを変更したか調査
設定はどうなっていた？ルール違反は？AWS ConfigS3公開設定やセキュリティグループ設定を評価
セキュリティ結果をまとめて見たいSecurity HubGuardDutyやInspector等のFindingsを集約

お金を気にしないなら全部採用すれば最強？

「必要な機能を重ねる」という方向性は正しいですが、使っていない領域のサービスまで無条件に有効化すれば強くなる、という話ではありません。例えばS3を使わなければMacieの優先度は低く、Webアプリを公開しなければWAFの出番も限定的です。

基本は多層防御（Defense in Depth）。IAM・ログ・暗号化などの土台を作り、その上でWeb、ワークロード、S3など自分の構成に合うサービスを追加します。

構成・要件追加を考えるサービス
AWSアカウントの基本防御IAM / CloudTrail / KMS / Config / GuardDuty / Security Hub
EC2・ECR・Lambdaを利用Inspector
Webサービスを公開WAF / Shield
S3に機密データMacie
DBパスワード・APIキーSecrets Manager

試験前の5問チェック

Q1. S3内の個人情報などを検出したい。何を使う？
答え： Amazon Macie。S3内の機密データ発見がキーワードです。
Q2. EC2に既知のソフトウェア脆弱性がないか確認したい。何を使う？
答え： Amazon Inspector。
Q3. AWS環境で不審な通信・挙動を検出したい。何を使う？
答え： Amazon GuardDuty。
Q4. 誰がAWS APIを実行したか追跡したい。何を使う？
答え： AWS CloudTrail。
Q5. GuardDutyやInspectorなどのセキュリティ結果を集約したい。何を使う？
答え： AWS Security Hub。
