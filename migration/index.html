ポイントを詳しく理解する

ここは試験で選択肢を見分けるために、用語だけでなく「何のために使うか」まで押さえます。

まず現状を把握する

Application Discovery Serviceなどでオンプレミスのサーバー情報を収集し、移行計画の材料にします。

サーバー移行とDB移行を分ける

サーバーワークロード移行はApplication Migration Service、データベース移行はAWS DMSというように対象でサービスが異なります。

Migration Hubで移行状況を追跡

複数の移行作業を一元的に確認する用途があります。

移行問題は『何を移すか』を見る

サーバー、DB、大量データ、ファイルなど対象を見れば候補サービスを絞りやすくなります。

試験ではどう考える？

問題文ではサービス名そのものではなく、要件や課題が提示されることがあります。まず「計算・保存・ネットワーク・セキュリティ・コスト」など目的を特定し、その目的に合うサービスへ絞り込みます。似たサービスが並んだ場合は、運用負荷、データ形式、接続方法、セキュリティ上の目的などの違いを確認します。

もう一段深く理解する

AWSへの移行では、Migration Hub、Application Discovery Service、Application Migration Service、Database Migration Service（DMS）などが目的別に使われます。

覚え方： Discovery＝調査、Migration＝引っ越し、DMS＝DB引っ越し。

似たサービスとの比較

Application Discovery Serviceオンプレ環境のサーバー情報を収集
Application Migration Serviceサーバーワークロード移行を支援
AWS DMSデータベース移行を支援
Migration Hub移行状況を一元的に追跡

試験での見分け方

  • 現状把握・依存関係調査→Discovery
  • サーバー移行→Application Migration Service
  • DB移行→DMS
  • 複数移行の進捗管理→Migration Hub

※ 試験ではサービス名だけでなく、要件・運用負荷・可用性・コストなどの条件から判断する問題が出ます。

3問ミニチェック

答えを考えてから開いて確認してください。

Q1. オンプレサーバーの情報収集に使うサービスは？
答え：AWS Application Discovery Service
Q2. データベース移行の代表サービスは？
答え：AWS Database Migration Service（DMS）
Q3. 移行進捗を一元管理するサービスは？
答え：AWS Migration Hub
