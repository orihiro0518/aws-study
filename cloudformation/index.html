AWS CloudFormationとは？

Infrastructure as Codeの考え方を初心者向けに理解する。

まず図でつかむ

Templateインフラをコードで定義
CloudFormation定義を読み取る
Stackまとめて管理
ResourcesAWSリソースを作成

覚え方： 名前を丸暗記するより「何をしたい時に使うか」を1行で説明できるようにすると、選択問題で判断しやすくなります。

ポイントを詳しく理解する

ここは試験で選択肢を見分けるために、用語だけでなく「何のために使うか」まで押さえます。

CloudFormationはAWS環境の設計図

EC2、VPCなどのAWSリソースをテンプレートへ記述し、まとめて作成・更新できます。

Infrastructure as Code（IaC）

インフラ構成をコードとして管理する考え方です。手作業だけの構築より再現性を高められます。

同じ環境を再現しやすい

開発環境と検証環境など、同じ構成を繰り返し作る場合に有効です。

変更履歴を管理しやすい

テンプレートをバージョン管理すれば『いつ何を変更したか』を追いやすくなります。

試験では自動化・標準化が目印

『手作業を減らしたい』『同じ環境を自動構築』『インフラをコード化』ならCloudFormationを考えます。

試験ではどう考える？

問題文ではサービス名そのものではなく、要件や課題が提示されることがあります。まず「計算・保存・ネットワーク・セキュリティ・コスト」など目的を特定し、その目的に合うサービスへ絞り込みます。似たサービスが並んだ場合は、運用負荷、データ形式、接続方法、セキュリティ上の目的などの違いを確認します。

もう一段深く理解する

AWS CloudFormationはインフラ構成をテンプレートとしてコード化し、自動作成・更新するInfrastructure as Code（IaC）サービスです。

覚え方： CloudFormation＝『AWS環境の設計図』。

似たサービスとの比較

CloudFormationAWSリソースをテンプレートで構築
手作業構築柔軟だが再現性・変更管理で不利
AWS CDKプログラミング言語で定義しCloudFormationへ合成

試験での見分け方

  • 同じ環境を何度も再現→CloudFormation
  • インフラ変更をコードレビュー→IaC
  • 手動設定ミスを減らしたい→テンプレート化

※ 試験ではサービス名だけでなく、要件・運用負荷・可用性・コストなどの条件から判断する問題が出ます。
