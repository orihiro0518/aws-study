AWS Well-Architected Framework

AWS設計の基本的な考え方を試験対策として整理する。

まず図でつかむ

運用Operational Excellence
安全Security
信頼性Reliability
性能・コスト・持続性Efficiency / Cost / Sustainability

覚え方： 名前を丸暗記するより「何をしたい時に使うか」を1行で説明できるようにすると、選択問題で判断しやすくなります。

ポイントを詳しく理解する

ここは試験で選択肢を見分けるために、用語だけでなく「何のために使うか」まで押さえます。

AWS設計を6つの柱で評価する

運用上の優秀性、セキュリティ、信頼性、パフォーマンス効率、コスト最適化、持続可能性の観点から設計を考えます。

Securityは保護

IAM、データ保護、検知などを通じてシステムや情報を守る観点です。

Reliabilityは障害へ耐える

障害から回復し、需要変化にも対応できる構成を考えます。複数AZなどの冗長化も関連します。

Cost Optimizationは無駄を減らす

必要な価値を保ちながら不要な支出を避ける考え方です。

サービス名ではなく設計原則の問題で登場

『AWSのベストプラクティスに沿ってアーキテクチャを評価』ならWell-Architectedを考えます。

試験ではどう考える？

問題文ではサービス名そのものではなく、要件や課題が提示されることがあります。まず「計算・保存・ネットワーク・セキュリティ・コスト」など目的を特定し、その目的に合うサービスへ絞り込みます。似たサービスが並んだ場合は、運用負荷、データ形式、接続方法、セキュリティ上の目的などの違いを確認します。

もう一段深く理解する

AWS Well-Architected Frameworkは、クラウド設計を評価・改善するためのベストプラクティス群です。運用上の優秀性、セキュリティ、信頼性、パフォーマンス効率、コスト最適化、持続可能性の柱があります。

覚え方： Well-Architected＝『AWS設計の健康診断チェックリスト』。

似たサービスとの比較

Securityデータ・システム・資産を保護
Reliability障害から回復し需要へ対応
Cost Optimization不要コストを避け価値を最大化
Performance Efficiency効率よくコンピューティング資源を利用

試験での見分け方

  • 単一障害点をなくす→Reliability
  • 過剰リソースを削減→Cost Optimization
  • 権限・保護設計→Security

※ 試験ではサービス名だけでなく、要件・運用負荷・可用性・コストなどの条件から判断する問題が出ます。
