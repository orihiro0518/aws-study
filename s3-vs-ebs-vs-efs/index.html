AWSストレージを用途から理解する

公開日：2026-09-01 ｜ 更新日：2026-09-03

S3・EBS・EFSを「倉庫・EC2のSSD・共有フォルダ」で整理し、S3 GlacierとStorage Gatewayまで一気に理解します。

まず結論：役割が違う

サービス一言イメージ主な用途こういう時に選ぶ
S3巨大なデータ倉庫画像・動画・ログ・バックアップ・データレイクオブジェクト単位で大量データを保存したい
EBSEC2のSSDOS・アプリ・DBファイルEC2から低レイテンシでディスクとして読み書きしたい
EFS共有フォルダ複数EC2で共有するファイル複数サーバーから同じファイルシステムを使いたい
S3 Glacier長期保管庫監査ログ・古いバックアップ・アーカイブほぼ使わないデータの保管料金を下げたい
Storage GatewayオンプレとAWSの橋ハイブリッドストレージ社内環境からS3等のAWSストレージを使いたい

覚え方： S3 = 倉庫 / EBS = EC2のディスク / EFS = 共有フォルダ。

S3が有名なのに、サーバー運用ではEBSを使うのはなぜ？

「S3が遅くてEBSが速いから」という理解だけだと少しズレます。大きな違いはアクセス方法とストレージの形です。

S3EBS
種類オブジェクトストレージブロックストレージ
EC2からの見え方APIでオブジェクトへアクセスOSからディスクとして扱う
レイテンシディスク用途より高め低レイテンシ
得意大量ファイル、静的コンテンツ、バックアップOS、アプリ、DB、頻繁な細かい読み書き

つまりEBS = サーバー内部で使うディスク、S3 = サーバーの外にあるオブジェクト置き場と考えると分かりやすいです。S3自体のスループットが低いという意味ではありません。

S3：オブジェクトを大量に保存する

S3はバケットの中に画像、動画、ログ、バックアップなどをオブジェクトとして保存します。Webアプリの画像置き場、ログ保管、バックアップ、データレイクなどが代表例です。

EC2のOSディスクのように「普通のSSD」として使うサービスではありません。アプリはS3 APIを通じてオブジェクトを読み書きします。

EBS：EC2に付けるブロックストレージ

EBSはEC2にアタッチして、LinuxやWindowsからディスクとして使います。ルートボリュームにOSを置いたり、アプリやDBファイルを保存したりします。

通常は特定のEC2に接続して使うイメージでOKです。なお、一部のEBSボリュームには同一AZ内の複数EC2へ接続できるMulti-Attach機能もあるため、「EBSは絶対に1台だけ」と覚え切らないのが正確です。

EBSはAZ単位のリソースなので、別AZへそのまま付け替えるものではありません。必要に応じてスナップショット等を使います。

EFS：複数EC2で共有するファイルシステム

EFSはネットワーク経由で利用するファイルストレージです。複数のEC2から同じファイルを共有したい場合に向いています。

例えばWebサーバーを3台に増やしても、ユーザーがアップロードしたファイルを全サーバーから同じように参照できます。標準的なRegional構成では複数AZから利用でき、One Zoneの選択肢もあります。

Webサーバーなら3つを同時に使うこともある

実際の構成では「S3かEBSかEFSのどれか1つ」ではありません。用途別に組み合わせます。

EC2
├ OS・アプリ        → EBS
├ DB用ディスク      → EBS（構成による）
├ 複数EC2の共有ファイル → EFS
└ 画像・バックアップ・ログ → S3

S3 Glacierは「S3の長期保管クラス」

現在の考え方では、GlacierはS3の中にある長期アーカイブ向けストレージクラスとして整理すると分かりやすいです。オブジェクトはS3に残ったまま、アクセス頻度と取り出し速度に応じてクラスを選びます。

ストレージクラス取り出し最低保存期間向いているデータ
S3 Glacier Instant Retrievalミリ秒でリアルタイム取得90日滅多に見ないが、必要時はすぐ取り出したい
S3 Glacier Flexible Retrieval数分〜数時間。復元処理が必要90日バックアップ・災害復旧・年に数回のアーカイブ
S3 Glacier Deep Archive数時間〜。復元処理が必要180日長期監査ログ・法令保存など、ほぼ取り出さないデータ

重要： Glacier系は保存料金を下げやすい代わりに、取り出し料金や最低保存期間があります。毎日読むデータをGlacierへ置くと、用途に合わずコスト面でも不利になり得ます。

Storage Gateway：オンプレとAWSストレージをつなぐ

Storage Gatewayは、オンプレミス環境からAWSクラウドストレージを利用するためのハイブリッドサービスです。既存の社内環境を一気にクラウドへ移せない場合でも、バックアップやアーカイブ先としてAWSを組み込みやすくします。

試験では「オンプレミスとAWSストレージの連携」「既存環境を維持しながらクラウドストレージを使う」といった要件がヒントです。

問題文から一発で選ぶ表

問題文選ぶもの
画像・動画・バックアップ・ログを大量保存S3
EC2のOSやDB用ディスクEBS
複数EC2で同じファイルを共有EFS
長期間ほぼ使わないデータを安く保管S3 Glacier
オンプレミスとAWSストレージを連携Storage Gateway

試験前の5問チェック

Q1. EC2のOSを保存するディスクとして使うのは？

答え：EBS。EC2へブロックストレージとして接続します。

Q2. 複数EC2から同じファイルを共有したい。何を使う？

答え：EFS。

Q3. 長期保存でほぼアクセスしない監査ログ。候補は？

答え：S3 Glacier系。特に長期間ほぼ取り出さないならDeep Archiveが候補です。

Q4. GlacierはS3と完全に別のデータ置き場？

答え：いいえ。現在はS3のGlacierストレージクラスとして理解するのが基本です。

Q5. オンプレのバックアップをAWSストレージへ連携したい。何を使う？

答え：Storage Gateway。
